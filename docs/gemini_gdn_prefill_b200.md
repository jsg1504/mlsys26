# 대규모 언어 모델의 Gated Delta Network (GDN) Prefill 단계 최적화 방법론 및 NVIDIA B200 아키텍처 기반 최적화 전략

## 대규모 언어 모델 추론의 패러다임 전환과 GDN의 부상

대규모 언어 모델(Large Language Model, LLM)의 성능이 기하급수적으로 향상됨에 따라, 모델이 처리해야 하는 컨텍스트 윈도우(Context Window)의 길이 역시 수천 토큰에서 수백만 토큰 단위로 확장되고 있다. 전통적인 트랜스포머(Transformer) 아키텍처에 기반한 소프트맥스(Softmax) 어텐션 메커니즘은 시퀀스 길이의 제곱에 비례하는 연산 복잡도와, 시퀀스 길이에 선형적으로 증가하는 Key-Value(KV) 캐시 메모리 요구량을 가진다.[1] 이는 긴 컨텍스트를 처리할 때 극심한 메모리 대역폭 병목과 용량 한계를 유발하며, 대규모 프로덕션 환경에서의 실시간 서빙을 어렵게 만드는 주된 요인으로 작용한다.[2]

이러한 한계를 근본적으로 극복하기 위해 제안된 것이 선형 어텐션(Linear Attention) 및 상태 공간 모델(State Space Model, SSM) 계열의 아키텍처이다. 이들은 기존의 소프트맥스 연산을 제거하고 고정된 크기의 은닉 상태(Hidden State) 행렬을 사용하여 과거의 정보를 압축함으로써, 시퀀스 길이에 대해 선형적인 연산 복잡도를 달성한다.[1, 3] 하지만 초기의 선형 모델들은 메모리를 누적하는 방식의 한계로 인해 특정 정보를 정확하게 검색(Retrieval)하거나 장기적인 문맥을 유지하는 연상 기억(Associative Recall) 능력이 기존 트랜스포머에 비해 현저히 떨어진다는 단점이 있었다.[4, 5] 

이를 해결하기 위해 등장한 혁신적인 아키텍처가 바로 Gated Delta Network (GDN)이다. GDN은 모델이 과거의 문맥을 상황에 맞게 적응적으로 망각할 수 있도록 하는 게이팅(Gating) 메커니즘과, 메모리 상의 특정 정보를 정밀하게 수정할 수 있도록 하는 델타 업데이트 규칙(Delta Update Rule)을 수학적으로 결합한 모델이다.[5, 6] 이 구조는 트랜스포머의 수술적인(Surgical) 정밀도와 순환 신경망(RNN)의 O(1) 메모리 복잡도라는 두 가지 장점을 모두 취하여, Qwen3.5, Qwen3-Next, OLMo Hybrid 등 최신 상용 모델 및 오픈소스 생태계에 널리 채택되고 있다.[7, 8, 9]

그러나 LLM의 추론은 사용자로부터 입력받은 전체 프롬프트를 한 번에 병렬로 처리하여 초기 상태를 구축하는 Prefill 단계와, 이후 토큰을 하나씩 순차적으로 생성하는 Decode 단계로 나뉘며, 이 두 단계는 완전히 다른 하드웨어 병목 특성을 보인다.[2, 10] Decode 단계가 메모리 대역폭(Memory Bandwidth)에 의해 제한을 받는 반면, Prefill 단계는 대량의 입력 토큰에 대한 행렬 연산을 동시에 수행해야 하므로 극심한 연산량(Compute-bound) 병목에 직면하게 된다.[2, 9, 11] GDN의 경우, 고정 크기의 상태 행렬을 구축하기 위해 복잡한 점화식과 비선형 활성화 함수를 시퀀스 전체에 걸쳐 계산해야 하므로 Prefill 단계에서의 연산 부하가 특히 심각하다.[5, 6]

나아가 인공지능 가속기 하드웨어의 발전 양상 역시 이러한 병목을 가중시키는 방향으로 변화하고 있다. NVIDIA의 최신 B200(Blackwell) 아키텍처는 5세대 텐서 코어(Tensor Core)를 도입하여 이전 세대인 H100(Hopper) 대비 부동소수점 연산 처리량을 2배 이상 끌어올렸으나, 반대로 공유 메모리(Shared Memory) 대역폭이나 비선형 함수 연산을 담당하는 특수 함수 유닛(Special Function Unit, SFU)의 성능은 그에 비례하여 확장되지 않는 '비대칭적 하드웨어 스케일링(Asymmetric Hardware Scaling)' 현상을 보여주고 있다.[12, 13] 따라서 GDN Prefill 단계를 B200에서 최적화하기 위해서는 단지 연산량을 줄이는 것을 넘어, B200 하드웨어의 미세 구조적 특성을 반영한 알고리즘과 커널의 코디자인(Co-design)이 필수적이다.[12, 13, 14] 본 보고서는 GDN 아키텍처의 Prefill 단계에서 발생하는 병목의 원인을 심층 분석하고, 이를 최적화하기 위한 최신 방법론들을 망라한 뒤, NVIDIA B200 아키텍처의 혁신적 기능들을 기반으로 GDN Prefill을 극한으로 가속할 수 있는 최적의 전략들을 선별 및 구체화한다.

## GDN 아키텍처 및 Prefill 단계의 수학적, 구조적 병목 분석

### Gated Delta Rule의 수학적 메커니즘과 연산 특성

Gated Delta Network의 핵심 연산은 기존 선형 어텐션의 단순 덧셈 기반 상태 갱신을 고도화된 Gated Delta Rule로 대체한 데 있다. 이는 시간 스텝 $t$에 따른 1차 선형 점화식(First-order linear recurrence)으로 정의되며, 크기 $d \times d$의 행렬 형태인 은닉 상태 $S_t$를 다음과 같이 업데이트한다.[5]

$$S_t = S_{t-1} (\alpha_t(I - \beta_t k_t k_t^\top)) + \beta_t v_t k_t^\top$$ [1, 5]

이 수식을 구성하는 각 요소는 고유한 인지적, 수학적 역할을 수행하며, 동시에 하드웨어 연산 관점에서의 과제를 부여한다.
먼저 $\alpha_t \in (0, 1)$는 데이터에 의존적인 스칼라 형태의 감쇠 게이트(Decay Gate)로서, 모델이 과거의 기억을 전역적으로 얼마나 보존할지 혹은 망각할지를 결정한다.[5, 15] 이는 시퀀스가 길어질수록 불필요한 노이즈가 누적되는 것을 방지하는 역할을 한다.[16, 17] 다음으로 $\beta_t \in (0, 1)$는 업데이트 게이트(Update Gate)로서, 새로운 입력이 기존 상태를 덮어쓰는 강도를 제어한다.[5, 15] 

수식 내의 $(I - \beta_t k_t k_t^\top)$ 항은 하우스홀더 변환(Householder transformation)과 수학적으로 유사한 구조를 가진다.[1, 18] 이 항은 새로운 키 벡터 $k_t$가 가리키는 방향에 존재하는 기존의 기억만을 선택적으로 소거하는 '표적화된 삭제(Targeted erasure)' 연산을 수행한다.[18] 이와 동시에 더하기 기호 뒤의 $\beta_t v_t k_t^\top$ 항을 통해, 방금 소거되어 비워진 메모리 공간에 새로운 정보(Value 벡터 $v_t$)를 기록하게 된다.[18] 이러한 수술적인 메모리 편집 능력이 GDN이 기존의 단순 선형 어텐션이나 Mamba 등의 모델을 뛰어넘어 복잡한 연상 기억 능력을 발휘하게 만드는 핵심 원리이다.[4, 5, 6]

그러나 하드웨어 추론 관점에서 볼 때, 이 수식은 심각한 연산 부하를 동반한다. $\alpha_t$와 $\beta_t$ 값을 구하기 위해서는 행렬 곱 연산 이후에 시그모이드(Sigmoid)나 SiLU(Sigmoid Linear Unit)와 같은 비선형 활성화 함수를 시퀀스의 모든 토큰에 대해 개별적으로 통과시켜야 한다.[5, 15] 더불어 상태 행렬 $S_t$를 갱신하기 위해서는 이전 상태 $S_{t-1}$의 결과가 반드시 필요하므로, 이론적으로는 $t$번째 토큰의 계산이 완료되기 전에는 $t+1$번째 토큰의 연산을 시작할 수 없는 엄격한 순차적 의존성(Sequential Dependency)을 띠게 된다.[6] 

### Prefill 단계의 병목: 연산 집약성(Compute-Bound)과 병렬화 한계

LLM의 텍스트 생성 과정은 근본적으로 Prefill과 Decode라는 이질적인 두 단계로 구성된다. Decode 단계는 이전에 생성된 상태를 읽어와 단일 토큰을 생성하는 과정을 반복하므로, 연산량 자체는 적지만 HBM(High Bandwidth Memory)에서 상태 행렬과 모델 가중치를 반복적으로 불러와야 하는 메모리 대역폭(Memory-bound) 병목에 시달린다.[2, 9] 반면, Prefill 단계는 수천에서 수십만 토큰에 달하는 사용자 프롬프트 전체의 문맥을 한 번에 해석하여 초기 GDN 상태 행렬 $S_t$를 구축해야 한다.[10]

이 과정에서 트랜스포머의 소프트맥스 어텐션은 시퀀스 내의 모든 토큰 쌍 간의 내적을 계산하여 $O(N^2)$의 연산을 수행하지만, 병렬 처리가 용이하다는 특징이 있다.[1] 반면 GDN은 연산 복잡도가 $O(N)$으로 줄어드는 대신, 앞서 언급한 점화식의 순차적 의존성 때문에 병렬 처리가 극히 어렵다.[1, 6] 만약 Prefill 단계에서 토큰을 하나씩 순차적으로 처리한다면, 최신 GPU의 수만 개의 코어 대부분이 유휴 상태(Idle)로 대기하게 되어 처리량이 극도로 저하된다.[6, 18] 따라서 GDN의 Prefill 단계는 이 순차적 점화식을 수학적으로 재구성하여 거대한 행렬 곱 연산으로 변환하고, 텐서 코어를 최대치로 가동해야 하는 철저한 연산 집약적(Compute-bound) 병목 구간이 된다.[2, 5, 9]

더욱이 컨텍스트 길이가 1K에서 16K 수준으로 길어지게 되면, 어텐션 및 상태 갱신 연산뿐만 아니라 각 층에 포함된 전방향 신경망(Feed-Forward Network, FFN)의 연산량이 폭발적으로 증가하여 전체 FLOPs의 지배적인 비중을 차지하게 된다.[11] GDN의 경우 3개의 GDN 선형 어텐션 레이어마다 1개의 일반 어텐션 레이어를 배치하는 하이브리드(Hybrid) 구조를 띠는 경우가 많아(예: Qwen 3.5), 어텐션 자체의 연산량은 최적화되더라도 이 거대한 FFN 계층들이 유발하는 행렬 곱 연산의 병목은 고스란히 남게 된다.[9, 14] 결론적으로 GDN Prefill 네트워크의 최적화는 순차적 점화식의 병렬화, 게이팅 연산을 위한 활성화 함수 오버헤드 최소화, 그리고 FFN 층의 연산량 절감이라는 다각도의 접근을 요구한다.

## GDN Prefill 가속을 위한 일반적 최적화 방법론

NVIDIA B200 아키텍처에 특화된 논의를 전개하기에 앞서, GDN을 포함한 선형 어텐션 아키텍처 전반의 Prefill 단계를 가속하기 위해 현재 인공지능 학계 및 산업계에서 널리 적용되고 있는 최상위 수준의 수학적, 시스템적 최적화 방법론들을 체계적으로 정리한다.

### 청크 단위 병렬화(Chunkwise Parallelization)와 WY 표현식

GDN 점화식의 엄격한 순차적 의존성을 타파하고 GPU의 텐서 코어를 활용하기 위한 가장 핵심적인 수학적 방법론은 '청크 단위 병렬화(Chunkwise Parallelization)'이다.[5, 6] 이 기법은 전체 시퀀스 $N$을 일정한 크기 $C$ (일반적으로 64~256)의 청크(Chunk) 여러 개로 분할하는 것에서 출발한다.[5, 19] 

시퀀스를 청크로 분할하게 되면, 연산은 청크 내부의 로컬 연산(Intra-chunk)과 청크 간의 상태 전달 연산(Inter-chunk)으로 나뉜다.[5, 19] 임의의 청크 $t$ 내부에 있는 $r$번째 위치의 상태 $S_r[t]$는 다음과 같이 수학적으로 분해될 수 있다.

$$S_r[t] = S[t] F_r[t] + G_r[t]$$ [5]

여기서 $S[t]$는 이전 청크로부터 전달받은 해당 청크의 초기 상태 행렬이다. $F_r[t]$는 청크 시작점부터 $r$번째 위치까지의 게이팅 및 감쇠 요인이 누적된 결과($\gamma_r[t] P_r[t]$)를 나타내며, $G_r[t]$는 오직 현재 청크 내부의 입력 토큰들만이 기여하여 생성된 로컬 상태 업데이트($\sum_{i=1}^r \frac{\gamma_r[t]}{\gamma_i[t]} \tilde{u}_i[t] k_i^\top[t]$)를 의미한다.[5] 

이러한 분해를 통해 각 청크 내부의 연산인 $F_r[t]$와 $G_r[t]$는 이전 청크의 결과인 $S[t]$를 기다릴 필요 없이 전체 시퀀스에 대해 완벽하게 독립적으로, 병렬로 계산할 수 있게 된다.[5, 6] 청크 내부 연산이 모두 병렬로 완료된 이후에만, 각 청크의 최종 상태를 다음 청크로 순차적으로 넘겨주는 가벼운 Inter-chunk 연산을 수행하면 된다.[5]

이 과정에서 특히 $I - \beta_t k_t k_t^\top$ 형태의 하우스홀더 행렬들의 연속적인 곱셈을 효율적으로 계산하기 위해 'WY 표현식(WY Representation)'이 적용된다.[5, 6] 본래 수치선형대수학에서 여러 개의 하우스홀더 반사(Householder reflections) 연산을 하나의 블록 행렬 연산으로 묶기 위해 고안된 WY 표현식은, 시퀀스에 따른 상태 행렬의 갱신 과정을 $O(d)$ 공간 복잡도만을 차지하는 콤팩트한 매개변수화로 변환한다.[6, 20] 결과적으로 GDN의 복잡한 델타 업데이트 규칙은 밀집 행렬 곱셈(Dense MatMul) 형태로 치환되어 GPU의 텐서 코어를 최대 효율로 사용할 수 있는 Compute-bound 작업으로 성공적으로 전환된다.[5, 6] 실제 구현에서는 이 모든 과정을 Flash-Linear-Attention이나 Triton과 같은 프레임워크를 사용하여 로컬 어텐션 연산, 상태 투영 연산, 그리고 상태 누적 과정을 단일 CUDA 커널 내에 융합(Kernel Fusion)함으로써 글로벌 메모리 I/O 오버헤드를 극단적으로 줄인다.[21, 22]

### 선형 어텐션 시퀀스 병렬화 (Linear Attention Sequence Parallelism, LASP)

프롬프트 길이가 수십만 토큰을 넘어 수백만 토큰에 이르게 되면, 병렬 연산을 수행하기 위한 활성화(Activation) 메모리의 크기가 단일 GPU의 HBM 용량을 초과하는 OOM(Out of Memory) 현상이 불가피하게 발생한다.[23, 24] 이를 해결하기 위해 여러 GPU에 시퀀스를 나누어 처리하는 시퀀스 병렬화(Sequence Parallelism, SP)가 필수적이다. 그러나 DeepSpeed-Ulysses나 Megatron-SP와 같은 기존의 트랜스포머용 SP 기법들은 시퀀스 길이 $N$에 비례하는 방대한 크기의 Key, Value 텐서를 GPU 간에 All-to-All 통신으로 교환해야 하므로, 통신 대역폭이 극심한 병목으로 작용한다.[23, 24]

반면 GDN과 같은 선형 아키텍처에 특화되어 개발된 LASP(Linear Attention Sequence Parallelism)는 행렬 곱셈의 결합 법칙을 교묘하게 활용한 '우측 곱셈 우선(Right-product-first) 커널 트릭'을 사용하여 이 문제를 해결한다.[23, 24] 기존 트랜스포머가 $Q K^\top$를 먼저 계산하여 $N \times N$ 어텐션 맵을 만드는 반면, 선형 어텐션은 $K^\top V$를 먼저 계산하여 $d \times d$ 크기의 고정된 상태 행렬을 만든다.[24] 

LASP는 전체 시퀀스를 청크 단위로 나누어 여러 GPU에 분산시킨 뒤, 각 GPU가 자신이 맡은 청크에 대해 로컬 상태 행렬 $KV$를 계산하도록 한다. 이후 점대점(Point-to-Point) 링(Ring) 통신 구조를 통해, $i$번째 GPU는 연산이 완료된 $d \times d$ 크기의 은닉 상태 행렬만을 $i+1$번째 GPU로 전달한다.[23, 24] 이 방식의 가장 큰 장점은 GPU 간 통신량이 시퀀스 길이 $N$과 완전히 독립적인 상수 크기($d \times d$)를 갖는다는 것이다.[24] LASP는 이러한 통신량의 극적인 감소와 더불어 내부 커널 융합 및 HBM을 활용한 상태 캐싱(State Caching)을 통해, 128개의 GPU 환경에서 무려 4096K(약 400만) 토큰 길이의 시퀀스를 병렬로 처리하는 데 성공하여 기존 SP 기법 대비 8배 이상 긴 확장성을 증명하였다.[23, 24]

### 예측적 FFN 희소성 (Predictive FFN Sparsity) 기법 적용

GDN의 선형적 특성 덕분에 어텐션 연산 자체의 병목은 완화되었으나, 반대로 FFN(전방향 신경망) 계층이 차지하는 연산 비중이 상대적으로 거대해지는 새로운 문제가 발생한다.[11] 특히 1K에서 16K 사이의 중간 규모 컨텍스트 길이의 Prefill 단계에서는 전체 FLOPs의 대부분이 FFN에서 발생한다.[11] 기존의 희소성(Sparsity) 기법들은 주로 순차적인 Decode 단계에 맞춰져 있어 병렬 Prefill 단계에 적용할 경우 정확도가 크게 떨어지거나 병렬성을 훼손하는 부작용이 있었다.[11]

이를 극복하기 위해 제안된 FastForward와 같은 예측적 FFN 희소성 프레임워크는 Prefill 단계의 거대한 행렬 연산 병렬성을 유지하면서도 연산량을 획기적으로 줄여준다.[11] 이 방법론은 청크 블록 단위로 가벼운 '전문가 예측기(Expert Predictor)'를 도입하여, 현재 처리 중인 토큰들의 문맥적 중요도를 평가하고 FFN 내부에서 가장 높은 중요도를 지닌 뉴런들만을 선택적으로 활성화한다.[11] 억제된 뉴런들로 인해 발생하는 연산 오차는 별도의 오차 보상 네트워크(Error Compensation Network)를 통해 실시간으로 교정되며, 계층별 희소성 스케줄러가 모델의 각 층마다 토큰 혼합(Token-mixing) 중요도를 평가하여 컴퓨팅 자원을 차등 분배한다.[11] 이 기법을 통해 LLaMA나 Qwen 아키텍처 기준 FFN 연산의 50%를 희소화하면서도 정확도 손실을 6% 미만으로 방어하고, Compute-bound 상태의 Prefill 속도를 1.45배까지 가속할 수 있다.[11]

### Disaggregated Serving 및 Chunked Prefill 아키텍처 도입

단일 알고리즘이나 커널 레벨을 넘어선 시스템(System-level) 단위의 최적화 기법 역시 GDN Prefill 가속에 핵심적인 역할을 단다. 가장 대표적인 것이 연산 특성이 이질적인 Prefill과 Decode 단계를 물리적으로 서로 다른 GPU나 노드에 분리하여 처리하는 Disaggregated Serving 기법이다.[25, 26]

일반적인 서빙 환경에서는 동일한 GPU 내에서 무거운 Prefill 요청과 가벼운 Decode 요청이 섞여 실행되며 자원 경합을 일으킨다. 특히 긴 프롬프트가 유입되면 Prefill 연산이 GPU의 컴퓨팅 자원을 독점하여, 진행 중이던 다른 사용자들의 Decode 응답이 일시적으로 멈추는 지연 스파이크(Latency Spike) 현상이 발생한다.[26, 27] Disaggregated Serving은 높은 TFLOPS를 갖춘 연산 지향적(Compute-optimized) GPU 그룹을 Prefill 전용으로 할당하여 대규모 청크 행렬 연산 효율을 극대화하고, 대용량 HBM을 갖춘 메모리 지향적(Memory-optimized) GPU 그룹을 Decode 전용으로 할당하여 동시 처리 사용자(Batch Size)를 극대화한다.[25, 26] Prefill 노드에서 계산이 완료된 상태 행렬(State Matrix) 및 KV 캐시는 고속 네트워크를 통해 즉각적으로 Decode 노드로 전송된다.[25] 특히 트랜스포머의 경우 막대한 용량의 KV 캐시를 노드 간에 전송해야 하는 오버헤드가 발생하지만, GDN의 경우 고정된 크기의 은닉 상태 행렬만을 전송하면 되므로 Disaggregated Serving 아키텍처와 완벽한 시너지를 발휘한다.[2, 14, 25]

단일 노드 내에서 자원 경합을 완화하는 대안적 시스템 기법으로는 Chunked Prefill이 있다.[28, 29] 이는 수만 토큰에 달하는 긴 Prefill 시퀀스를 한 번의 거대한 포워드 패스(Forward Pass)로 처리하는 대신, 더 작은 크기의 여러 청크로 쪼개어 현재 진행 중인 다수의 Decode 스텝들과 교차(Interleave)하여 스케줄러에 주입하는 방식이다.[28] 이를 통해 긴 프롬프트 처리 중에도 다른 요청의 토큰 생성이 멈추지 않도록 보장하여, 전체적인 Time-to-First-Token(TTFT)과 응답 지연의 일관성을 획기적으로 개선한다.[28]

## NVIDIA B200(Blackwell) 아키텍처의 혁신적 하드웨어 특성 분석

앞서 서술한 GDN Prefill 최적화 기법들이 실제 물리적 하드웨어 상에서 100%의 잠재력을 발휘하려면 타겟 플랫폼의 미세한 아키텍처 특성을 정확히 이해해야 한다. 최신 AI 가속기인 NVIDIA B200 아키텍처는 이전 세대인 H100(Hopper)과 비교하여 구조적으로 근본적인 변화를 맞이했으며, 특히 '비대칭적 하드웨어 스케일링(Asymmetric Hardware Scaling)'이라는 현상이 최적화의 새로운 변수로 떠올랐다.[12, 13]

### 비대칭적 하드웨어 스케일링과 SFU 병목의 부상

B200은 5세대 텐서 코어를 탑재하여 기본 부동소수점(FP16/BF16) 연산 처리량(Throughput)이 H100 대비 2.25배 증가한 2.25 PFLOPS에 달하는 압도적인 행렬 곱(MMA) 능력을 자랑한다.[12, 13] 하지만 이토록 눈부신 텐서 코어의 발전 속도와는 대조적으로, 스트리밍 멀티프로세서(SM) 내부에 위치한 공유 메모리(Shared Memory)의 대역폭이나 지수 함수(Exponential), 로그 함수 등 복잡한 비선형 수학 연산을 전담하는 특수 함수 유닛(Special Function Unit, SFU)의 개수 및 성능은 H100 세대와 동일한 수준에 머물러 있다.[12, 13]

이러한 하드웨어 발전의 불균형은 커널 최적화의 패러다임을 완전히 뒤바꾸어 놓았다. 과거 H100 시대에는 어떻게든 텐서 코어에 데이터를 빨리 공급하여 행렬 곱 속도 자체를 높이는 데 집중했다면, B200에서는 오히려 너무 빠른 텐서 코어의 속도를 다른 유닛들이 따라가지 못해 병목이 발생한다.[13] 특히 어텐션 메커니즘이나 GDN 점화식에 필수적인 소프트맥스(Softmax) 또는 게이팅 활성화 함수의 지수 연산을 수행할 때, 한정된 SFU(MUFU.EX2) 자원에 병목이 발생하여 거대한 텐서 코어들이 연산을 멈추고 대기(Stall)하는 사태가 벌어지게 된다.[12, 13] 

### 텐서 메모리(TMEM)의 도입과 레지스터 압력의 해소

비대칭적 스케일링 문제를 완화하고 텐서 코어의 활용도를 극대화하기 위해 B200 아키텍처가 새롭게 도입한 가장 혁신적인 구성 요소가 바로 '텐서 메모리(Tensor Memory, TMEM)'이다.[12, 13] TMEM은 각 SM 내부에 256KB 크기로 할당된 전용 온칩(On-chip) 스크래치패드 메모리 계층으로, 기존의 L1 캐시나 공유 메모리와는 완전히 다른 목적을 가진다.[12, 13, 30]

기존 세대(Hopper)에서는 텐서 코어가 행렬 곱-누산(MMA) 연산을 수행한 뒤 그 중간 결과물(Accumulators)을 범용 레지스터(Registers)에 저장해야 했다. 이로 인해 레지스터 파일에 극심한 압력(Register Pressure)이 가해져, 한 번에 처리할 수 있는 병렬 스레드 수나 행렬 타일(Tile)의 크기가 제한되었다.[12, 13] 반면 B200의 TMEM은 텐서 코어와 직접적이고 긴밀하게(Warp-synchronous) 연결되어 있어, MMA 유닛이 연산 결과를 레지스터를 거치지 않고 곧바로 TMEM에 기록하고 읽어올 수 있다.[12, 13, 31] 결과적으로 레지스터 고갈 문제가 근본적으로 해소되었으며, 커널 개발자는 기존의 64x128 크기였던 연산 타일을 최대 128x256x16 크기까지 2배 이상 확장하여 더 큰 규모의 병렬 연산을 한 번에 스케줄링할 수 있게 되었다.[12, 13, 32]

### 비동기 5세대 텐서 코어 및 2-CTA MMA 모드 지원

B200의 5세대 텐서 코어는 `tcgen05.mma`라는 새로운 PTX 명령어를 통해 완전한 비동기(Fully Asynchronous) 실행 능력을 획득했다.[13, 32] 기존 아키텍처에서는 행렬 곱 연산이 끝날 때까지 해당 워프(Warp)가 다른 명령을 내리지 못하고 대기해야 했으나, B200에서는 MMA 유닛이 독립적으로 TMEM에 연산 결과를 누적하는 동안, 동일한 워프가 즉시 다음 데이터를 공유 메모리나 글로벌 메모리에서 로드하는 등의 데이터 이동 명령을 비동기적으로 중첩(Overlap)하여 발행할 수 있다.[12, 13]

나아가 B200은 동일한 클러스터 내에 존재하는 두 개의 개별 스레드 블록(CTA, Cooperative Thread Array)이 협력하여 하나의 거대한 행렬 곱(UMMA)을 수행하는 2-CTA MMA 모드를 지원한다.[13, 32] 이 모드에서는 리더 CTA의 단일 스레드가 연산 명령을 내리면, 두 CTA가 각자 소유한 TMEM 공간을 논리적으로 하나처럼 병합하여 연산을 분담한다.[13, 32] 이를 통해 데이터를 공유 메모리에서 TMEM으로 중복해서 읽어와야 했던 기존의 메모리 트래픽 한계를 극복하고, 글로벌 동기화 횟수를 획기적으로 줄일 수 있다.[13] 

### NVFP4 양자화 포맷과 마이크로 텐서 스케일링

모델의 크기가 수백 빌리언 파라미터를 넘어서면서 메모리 용량과 대역폭의 한계가 물리적으로 다가오자, NVIDIA는 B200에 업계 최초로 4비트 부동소수점(FP4) 연산을 하드웨어 네이티브로 가속하는 기능을 탑재했다.[14, 33] 과거의 단순한 4비트 정수(INT4)나 4비트 부동소수점 방식은 데이터의 해상도를 심각하게 훼손하여 LLM의 추론 정확도를 떨어뜨리는 치명적인 약점이 있었다.[34, 35]

이를 극복하기 위해 설계된 B200의 독자 포맷인 NVFP4는 극단적인 압축 환경에서도 정확도를 보존하는 '마이크로 텐서 스케일링(Micro-Tensor Scaling)'이라는 2단계(Two-level) 스케일링 전략을 사용한다.[14, 36, 37]
1.  **데이터 표현**: 개별 데이터 요소는 1비트 부호(Sign), 2비트 지수(Exponent), 1비트 가수(Mantissa)로 구성된 E2M1의 극소형 4비트 포맷으로 저장된다.[34, 37]
2.  **블록 레벨 스케일링 (Micro-block scaling)**: 16개의 데이터 요소를 하나의 마이크로 블록(Micro-block)으로 묶고, 이 16개의 값이 고정밀도의 8비트 부동소수점(E4M3, FP8) 스케일링 팩터를 공유하도록 한다.[36, 37] 경쟁 규격인 MXFP4가 32개 요소를 묶고 지수부만 있는 E8M0 스케일링을 사용하는 것에 비해, NVFP4는 그룹 크기를 절반으로 줄여 아웃라이어(Outlier)에 대한 국소적인 적응력을 크게 높였으며 가수부(Mantissa)가 포함된 E4M3를 사용하여 소수점 스케일링의 정밀도를 비약적으로 향상시켰다.[36, 37, 38]
3.  **텐서 레벨 스케일링**: 미세한 블록 스케일링 위에서, 전체 텐서 단위에 적용되는 FP32 스케일링 팩터를 추가로 적용하여 텐서 전반의 거시적인 동적 범위(Dynamic Range)를 수용한다.[34, 36]

B200의 5세대 텐서 코어는 이러한 복잡한 2단계 스케일링 요소를 동적으로 해석하고 4비트 행렬 곱 연산을 수행하는 과정을 하드웨어 내부에서 자동으로 처리한다.[37, 39] 이를 통해 개발자는 FP8 대비 메모리 사용량을 최대 4배까지 줄이면서도 추론 성능(Throughput)을 2배 이상 끌어올릴 수 있으며, 400B 이상의 초대형 모델에서도 정확도 하락(Accuracy Drop)을 기준선 대비 무시할 수 있는 수준으로 억제할 수 있다.[14, 37, 40] 

### FlashAttention-4 (FA4)의 알고리즘-커널 코디자인 혁신

NVIDIA B200의 비대칭적 하드웨어 특성을 소프트웨어적으로 100% 활용하기 위해 개발된 대표적인 레퍼런스가 FlashAttention-4 (FA4) 알고리즘이다.[12, 13] FA4가 제시한 최적화 파이프라인은 단순히 소프트맥스 연산에 국한되지 않고, GDN과 같은 다른 선형 어텐션 커널 구조를 B200에 맞게 최적화하는 데 있어 중요한 방법론적 템플릿을 제공한다.[13, 41, 42]

*   **소프트웨어 에뮬레이션 (Software-Emulated Exponential)**: 하드웨어의 지수 함수 유닛(MUFU.EX2) 병목을 해결하기 위해, FA4는 남아도는 부동소수점 곱셈-덧셈(FMA) 유닛을 활용하여 지수 연산을 소프트웨어적으로 에뮬레이션한다.[13] 실수 연산을 정수부와 소수부로 분해한 뒤(Cody-Waite 축소), 소수부에 대해 Horner의 다항식 근사법(Polynomial Approximation)을 적용하여 소프트웨어적으로 지수 값을 산출해낸다.[12, 13]
*   **5단계 파이프라인 및 핑퐁 스케줄링**: 이전 세대의 2단계 파이프라인을 확장하여 로드(Load), 계산(Compute), 소프트맥스/정규화, 리스케일(Rescale), 저장(Store)의 5단계 워프 전문화(Warp Specialization) 파이프라인을 구축했다.[41, 42] 핵심은 핑퐁 스케줄링(Ping-pong Scheduling)으로, 여러 개의 쿼리 타일($Q^H, Q^L$)을 교대로 스케줄링하여 한 워프가 지수 함수를 계산하는 동안 다른 워프가 텐서 코어를 사용하도록 연산을 완벽하게 엇갈리게(Overlap) 배치한다.[13]
*   **조건부 리스케일링 (Conditional Online Rescaling)**: 행렬 업데이트 시 발생하는 보정 연산(Rescaling)의 횟수를 극단적으로 줄이기 위해, 이전 타임스텝과의 최댓값 차이가 미리 설정한 임계값(Threshold, $\tau$)을 초과할 때만 보정 연산을 수행하고, 임계값 미만일 때는 무시하다가 최종 단계에서 한 번에 정규화하는 논리를 적용하여 SFU 연산 오버헤드를 10분의 1 수준으로 줄였다.[13, 42]

## NVIDIA B200 아키텍처 기반 GDN Prefill 최적화 선별 방법론

지금까지 분석한 GDN Prefill의 수학적, 알고리즘적 연산 특성과 NVIDIA B200의 하드웨어 및 마이크로아키텍처 특성을 교차 분석하면, B200 환경에서 GDN Prefill 네트워크의 잠재력을 한계치까지 끌어올리기 위해 전략적으로 조합해야 할 최적화 방법론들이 명확해진다. 
단순히 연산 정밀도를 낮추거나 캐시를 관리하는 것을 넘어, 하드웨어의 비대칭적 병목을 소프트웨어적으로 우회하고 고유의 온칩(On-chip) 자원을 GDN의 수학적 특성에 맞추어 맵핑하는 고도의 코디자인(Co-design) 전략 4가지를 도출하였다.

### 1. TMEM 및 비동기 MMA를 활용한 WY 표현식 상태 누적 커널 코디자인

GDN의 Prefill 단계에서 가장 막대한 TFLOPS를 소비하는 연산은 청크 단위 병렬화를 수행할 때 발생하는 WY 표현식의 행렬 누적(State Accumulation) 연산이다. 수식 $S_r[t] = S[t] F_r[t] + G_r[t]$를 계산하기 위해서는 막대한 크기의 하우스홀더 랭크-1 행렬 업데이트 결과물인 $W$ 행렬과 $Y$ 행렬을 연속적으로 생성하고 누적해야 한다.[5] 이 과정에서 중간 상태(Intermediate States)를 계속해서 읽고 써야 하므로, 이전 세대 GPU에서는 범용 레지스터 용량 부족(Register Spilling)과 공유 메모리 대역폭 고갈이 치명적인 병목으로 작용했다.[12]

**적용 전략:**
B200에서는 GDN의 청크 커널을 작성할 때(예: CuTe-DSL 프레임워크 활용), WY 표현식을 구성하는 거대한 누산기(Accumulator) 변수들을 레지스터나 공유 메모리가 아닌 256KB의 **텐서 메모리(TMEM)**에 명시적으로 할당하도록 코드를 재설계해야 한다.[12, 13] TMEM은 텐서 코어와 직접 연동되어 있으므로, 비동기 명령어인 `tcgen05.mma`를 사용하여 행렬 곱셈의 결과물이 레지스터를 거치지 않고 TMEM의 32-column 단위 과립(Granule)에 바로 누적되도록 파이프라인을 구성한다.[12, 13]

**효과 및 유용성:**
이 기법이 적용되면 레지스터 압박이 완전히 사라지게 되어, GDN 커널이 한 번에 스케줄링할 수 있는 타일(Tile)의 크기를 H100 시절(예: 64x128) 대비 2배 이상 큰 128x256x16 크기로 대폭 확장할 수 있다.[12, 13] 타일 크기의 확장은 글로벌 메모리와 공유 메모리로의 데이터 왕복 횟수를 급감시킨다. 나아가, TMEM에서 $G_r[t]$ 연산이 행렬을 갱신하는 동안, 완전 비동기 특성을 이용해 다음 청크의 $K, V$ 데이터를 텐서 메모리 가속기(TMA)를 통해 백그라운드에서 로드하도록 중첩(Overlap)시킴으로써, B200의 5세대 텐서 코어 활용률을 이론적 최대치인 70% 이상으로 유지할 수 있다.[12, 13]

### 2. 하드웨어 비대칭성을 우회하는 FMA 기반 지수/게이팅 에뮬레이션 및 핑퐁 스케줄링

GDN의 수식적 핵심은 적응적 망각을 수행하는 $\alpha_t$ (감쇠 게이트)와 $\beta_t$ (업데이트 게이트)에 있다.[5, 15] 이 값들을 계산하기 위해서는 선형 투영 이후 시그모이드(Sigmoid)나 SiLU와 같은 비선형 활성화 함수를 시퀀스 전체 토큰에 대해 개별적으로 통과시켜야 한다. 하지만 B200은 행렬 연산 능력(2.25 PFLOPS)에 비해 이러한 활성화 함수를 처리하는 특수 함수 유닛(MUFU.EX2 등 SFU)의 성능이 상대적으로 빈약한 '비대칭적 스케일링' 특성을 지니고 있다.[12, 13] 따라서 GDN의 게이팅 연산을 하드웨어 SFU에만 맡겨두면, 연산이 끝날 때까지 거대한 텐서 코어들이 멈춰 서는 참사가 발생한다.

**적용 전략:**
FlashAttention-4가 제시한 혁신적인 방법론을 GDN 게이팅 커널에 직접 이식해야 한다. GDN의 활성화 함수(시그모이드/SiLU의 지수 연산부)를 처리할 때, 정체된 하드웨어 MUFU 유닛 대신 유휴 상태로 남아도는 부동소수점 곱셈-덧셈(FMA) 범용 연산 유닛을 활용하여 **소프트웨어적으로 에뮬레이션(Software-Emulated Exponential)**한다.[12, 13] 수식을 정수부와 소수부로 나누고, 소수부는 Horner의 다항식 근사법(Polynomial Approximation)을 사용해 일련의 FMA 파이프라인 명령어로 변환하여 계산한다.[13]
이와 동시에 커널 내부에 5단계(Load-Compute-Gate-Rescale-Store)로 분업화된 워프 전문화(Warp Specialization)를 구현하고, 다중 타일에 대한 **핑퐁 스케줄링(Ping-pong Scheduling)**을 적용한다.[13, 41]

**효과 및 유용성:**
핑퐁 스케줄링을 통해 한 워프 그룹(Warp Group)이 $t$번째 청크의 게이팅 변수($\alpha_t, \beta_t$)를 FMA 소프트웨어 에뮬레이션으로 계산하고 있는 그 순간에, 다른 워프 그룹은 이미 구해진 $t-1$번째 게이팅 변수를 기반으로 텐서 코어를 점유하여 거대한 WY 행렬 곱(MMA)을 쉼 없이 수행할 수 있게 된다.[13] 이로써 B200의 가장 치명적인 약점인 SFU 병목이 완벽히 마스킹(Masking)되며, GDN 특유의 무거운 게이팅 메커니즘이 더 이상 Prefill 속도 저하의 원인이 되지 않는다.

### 3. GDN 투영 층 및 예측적 FFN 가속을 위한 NVFP4 마이크로 스케일링 통합

GDN 블록은 어텐션 수식을 위한 입력 투영($q, k, v$)과 게이팅 파라미터 투영($\alpha, \beta, \gamma$), 그리고 출력 투영 등 막대한 양의 선형 투영(Linear Projections) 계층을 수반하며, 모델이 대형화될수록 그 뒤에 따르는 FFN 계층이 연산의 절반 이상을 차지하게 된다.[5, 11] B200 환경에서는 모델의 가중치 및 KV 입출력을 극단적으로 압축하여 대역폭을 확보하는 것이 필수적이다.

**적용 전략:**
모델의 모든 투영 층 및 FFN 층 가중치를 B200의 네이티브 포맷인 **NVFP4 양자화 포맷**으로 전면 전환하여 서빙 환경(예: vLLM, TensorRT-LLM)을 구축한다.[5, 36, 43] 특히 GDN은 게이팅을 통해 아웃라이어(Outlier) 값이 빈번하게 발생할 수 있으므로, 단순 INT4나 MXFP4 대신 16개 요소 단위로 E4M3 스케일링 팩터를 정밀하게 적용하는 **마이크로 블록 스케일링(Micro-block scaling)**을 활성화해야 한다.[14, 36, 37]
이에 더해, 앞서 일반적 방법론으로 언급된 **예측적 FFN 희소성(Predictive FFN Sparsity)** 기법을 NVFP4 텐서 코어 파이프라인 위에 통합한다.[11] 

**효과 및 유용성:**
NVFP4 포맷의 적용은 HBM에서 가중치와 상태 행렬을 읽어오는 대역폭 소모를 FP8 대비 절반으로 줄여, GDN의 고정 크기 은닉 상태 전송 및 업데이트 속도를 극한으로 끌어올린다.[14, 36] 또한 B200의 전용 FP4 네이티브 텐서 코어가 활성화됨에 따라, GDN의 방대한 투영 연산 처리량(Throughput)이 단순 수치상으로 2배 이상 폭발적으로 증대된다.[14, 34] 여기에 예측적 희소성 기법이 결합되면, 연산량이 큰 FFN 블록의 50%를 아예 건너뛰면서도 남은 50%를 4비트 속도로 처리하게 되어, 정확도 손실(<6%) 없이 Prefill 단계의 가장 거대한 Compute-bound 벽을 돌파할 수 있다.[11]

### 4. GDN 상태 특화 Disaggregated Serving 및 NVLink 가속 LASP 도입

단일 GPU 수준을 넘어 GB200 NVL72와 같은 대규모 랙 스케일(Rack-scale) B200 클러스터 환경에서 GDN을 배포할 경우, 시스템 레벨의 네트워크 토폴로지 최적화가 시너지를 극대화한다.[14]

**적용 전략:**
첫째, 수백만 토큰 단위의 문서나 코드를 처리할 때 **선형 어텐션 시퀀스 병렬화(LASP)** 기법을 도입하되, B200 클러스터의 핵심인 1.8 TB/s 단방향 통신 대역폭을 제공하는 **5세대 NVLink 및 NVSwitch** 아키텍처에 통신 링(Ring)을 맵핑한다.[14, 23, 24, 44]
둘째, 클러스터의 자원 분배를 완전히 이원화하는 **Disaggregated Serving (Prefill-Decode 분리)** 아키텍처를 도입한다.[25, 26, 27] 

**효과 및 유용성:**
이러한 시스템적 접근은 트랜스포머보다 GDN 모델에서 그 효용성이 몇 배로 증폭된다. 일반적인 트랜스포머는 Disaggregated Serving을 적용할 때 Prefill 노드에서 계산된 거대한 크기의 KV 캐시 전체를 Decode 노드로 네트워크를 통해 넘겨주어야 하는 극심한 통신 오버헤드(Routing overhead)가 발생한다.[9, 25] 하지만 GDN 아키텍처는 시퀀스 길이와 무관한 고정 크기($d \times d$)의 상태 행렬(State Matrix)만을 지니고 있다.[2, 14] 
따라서 초고속 NVSwitch 네트워크를 통해 이 작고 압축된 상태 행렬만을 찰나의 순간에 Compute 전용(Prefill) 노드에서 Memory 전용(Decode) 노드로 라우팅할 수 있다.[25, 45] LASP 병렬화 단계에서도 NVLink의 압도적인 대역폭 덕분에 GPU 간 청크 상태 동기화 지연이 사실상 0에 수렴하게 된다.[24] 결과적으로 긴 프롬프트 연산이 사용자 생성 응답을 가로막는 지연 스파이크(Tail latency)를 근본적으로 제거하고, 대규모 동시 접속 환경에서 균일하고 쾌적한 Time-to-First-Token(TTFT)을 보장할 수 있다.

## 결론 및 제언

대규모 언어 모델의 Gated Delta Network(GDN)는 수술적인 정밀도를 가진 게이팅 메커니즘과 고정 크기의 델타 메모리 갱신을 통해 무한한 컨텍스트를 선형적인 비용으로 이해할 수 있는 차세대 기반 아키텍처다. 그러나 추론의 첫 관문인 Prefill 단계에서는 GDN 특유의 순차적 점화식과 방대한 투영 연산, 그리고 복잡한 비선형 게이팅 활성화 함수로 인해 GPU의 컴퓨팅 자원을 한계까지 몰아붙이는 극심한 연산량(Compute-bound) 병목이 필연적으로 발생한다.

최신 인공지능 가속기인 NVIDIA B200(Blackwell) 아키텍처는 텐서 코어의 비약적인 발전으로 이러한 컴퓨팅 한계를 돌파할 하드웨어적 잠재력을 제공한다. 하지만 B200 고유의 '비대칭적 하드웨어 스케일링(Asymmetric Hardware Scaling)' 특성으로 인해, 기존 세대의 코드를 단순히 이식하는 것만으로는 특수 함수 유닛(SFU)과 메모리 대역폭의 불균형이라는 새로운 벽에 부딪히게 된다. 

결론적으로 B200 환경에서 GDN Prefill의 성능을 최고조로 끌어올리기 위해서는 다음과 같은 4단계의 고차원적인 알고리즘-하드웨어 코디자인(Co-design) 최적화가 필수적으로 요구된다.

1.  **TMEM 기반 청크 커널 융합**: 256KB의 텐서 메모리(TMEM)에 WY 표현식의 거대한 누산 변수를 직접 유지하고, 5세대 텐서 코어의 비동기적 특성(`tcgen05.mma`)을 결합하여 레지스터 부족과 메모리 대기 시간을 완벽히 은닉(Masking)해야 한다.
2.  **지수 함수 소프트웨어 에뮬레이션**: 하드웨어의 특수 함수 유닛(SFU)에 전적으로 의존하던 $\alpha_t, \beta_t$의 지수 게이팅 연산을 유휴 상태의 FMA 유닛을 통한 다항식 근사로 대체하고 핑퐁 스케줄링을 적용하여 연산 정체를 우회해야 한다.
3.  **NVFP4 마이크로 스케일링 적용**: 모델 투영 및 FFN 레이어에 B200 네이티브 NVFP4 양자화(E4M3 기반 16요소 마이크로 블록)를 도입하여, 메모리 대역폭 한계를 돌파하고 연산 처리량을 2배 이상 배가시켜야 한다.
4.  **GDN 특화 Disaggregated Serving과 NVLink LASP**: GB200 NVL72 시스템의 NVSwitch를 활용하여, 고정 크기 상태 벡터라는 GDN의 수학적 강점을 십분 발휘하는 Prefill/Decode 분할 아키텍처 및 선형 시퀀스 병렬화 링(Ring) 통신망을 구축해야 한다.

이러한 최적화 방법론들을 vLLM, TensorRT-LLM, SGLang과 같은 최신 추론 서빙 프레임워크 수준에서 유기적으로 구현하고 연동한다면, 기업 및 연구 기관은 수백만 토큰 이상의 길이를 처리해야 하는 RAG 파이프라인이나 에이전틱(Agentic) AI 애플리케이션의 실시간 추론 레이턴시와 운용 비용을 이전 세대 대비 획기적인 수준으로 혁신할 수 있을 것이다.
